# 0.6.1 material and Castle model audit

Read-only inspection on 2026-10-18. `python tools/verify_workspace.py --storage-only` passed before reading external release data. No source, art, archive, Blender scene or native cook was changed.

## Packaged 0.6.0 facts

The final 0.6.0 candidate is `output/release_060/assembly/candidate-r2/community_civilization_pack.sga` (SHA-256 `204a889662e2b403b5c0caccb4b79f08bdf0654f90b5f9095ebebfd773b641c8`). `output/release_060/qualification/final-archive-r2/receipt.json` records all Castle art members as byte-identical to the 0.5.3 base. `sga-archiver list --filter art/scenario/cccastle/imperial_citadel/model` shows the Citadel RGM, RGO, RRGeom and RRMaterial under the `data` TOC; the 0.6.0 candidate contains the custom material and texture resources. The 0.6.0 unit identities have a separate archive TOC fault under investigation by the release integrator.

The retained 0.5.3 Castle material change modified only `options.z` from 0 to 1 in three `rrmaterial` resources. The user confirmed both stock-model controls rendered on the same landmark actor/stamp paths in 0.5.2 Diagnostic A. The 0.5.3 custom material probe was never accepted in a native match, and the current 0.6.0 user report says both custom Castle landmarks remain invisible. Consequently the `options.z` edit did not establish a repair. The 0.5.1 selector-name repair was also unproven and the 0.5.2 diagnostic found working Feudal stock models without those names.

Directly parsed the 0.5.2 Test C Castle `model.rrgeom` readbacks, whose hashes are retained by 0.6.0. Citadel has four vertex/index pairs, with 41,264 / 35,691 / 35,798 / 35,792 vertices. Headquarters has 41,493 / 36,586 / 36,549 / 36,454. Each vertex stream has stride 24. The four half-float position lanes and two half-float UV lanes are finite for every vertex; all indices are in range and every indexed triangle is nondegenerate. The earlier Garrison `non-finite UV` diagnostic in the 0.5.1 report concerns the monastery body, not these Castle models.

Each Castle RRGeom GOHD uses `structure_collection`. Each RRMaterial contains a matching named `*_pbr_atlas_collection` GMat and a base GMat. All 39 texture slots in both GMat roots of each Castle material have zero missing `art/` paths against the 0.6.0 final archive inventory. This establishes static resource closure, not rendering.

Both retained Castle `building.json` sources use the Garrison `english-house` profile. Their 0.5.0 handoffs identify different stock Chinese landmark owners: Great Wall wonder for the Citadel and HA01 Castle landmark B for Headquarters. The stock Great Wall model decodes as `structure_collection`; the HA01 Castle landmark B model decodes as `Structure`. The English House model was cooked and later grafted under those different native landmark owners, with RGM selector and material parameter patches in 0.5.1/0.5.3. This cross-profile model/RGO compatibility remains the strongest structural hypothesis, but no binary field examined here proves it is the sole engine rejection.

## Isolated native static decoder and selector audit

`python -B tools/release_061/decode_castle_static_061.py` built an isolated SQLite index from the exact 0.6.0 SGA and ran the installed Garrison core's `convert decode-static` for the two custom Castle models. Both returned exit code 0. Their manifests and logs are under `output/release_061/castle-static-decode`; the installed game asset index was untouched. Each reports four `structure_collection` geometry groups, complete texture decoding (eight textures, zero missing), no blockers or warnings. This is a static decoder result, not game rendering.

The Castle MSCL declares seven source parts (`garrison_part_0000` through `0006`). Its MSBP declares six selectors and contains six paired MSD/CNBP records. This header and pair-count pattern matches an accepted 0.4.0 building. The 0.5.1 condition builder emits the same `(opcode=2, flag=0, one=1, life_cycle_state)` shape found in stock landmark multi-state predicates. Stock selectors with many mutually exclusive lifecycle states show that these records are alternatives; the old `visible()` union is a plausible static interpretation. The 0.5.0 selectors already selected the full healthy compound by that interpretation, before the 0.5.1 renaming, so a missing `sel_healthy` name cannot alone explain both releases' invisibility.

The selected parts contain real triangles. Citadel group 0 has 492 foundation, 22,608 primary healthy, 1,968 ruin and 540 heavy-damage triangles. Its other three groups have 22,596, 22,596 and 22,602 healthy triangles. The 0.5.1 healthy selector's 492 + 22,608 + 22,596 + 22,596 + 22,602 = 90,894 triangles, exactly matching the retained handoff. Headquarters has 564 foundation plus 22,908 + 22,906 + 22,932 + 22,924 healthy triangles = 92,234, also exactly matching its handoff. The heavy-damage parts include nonempty native geometry as well. This rejects a missing-part or zero-triangle selector explanation.

Both decoded custom models report `structure_collection_contract_status: unsupported` and `no qualified StructureCollection tail contract`. However accepted 0.4.0 One Pillar and Phổ Minh controls also produce that decoder status (their effect is `object_collection`), so this is a decoder qualification limit rather than proof that AoE4 rejects the Castle models. A 0.4.0 blacksmith control refused this decoder with nonfinite UV, reinforcing that decoder success/failure cannot stand in for a native render test.

## Minimum next discriminating step

Keep the custom FBX, seven visual parts, textures, selectable ruin geometry and native landmark actors. Run a fresh supported static model cook for one representative custom Castle model against its exact landmark-compatible native owner/template, using new 0.6.1 paths and the shared native lock. Verify readback quartet, descriptors, material names, finite streams, texture closure, archive TOCs and unaffected member hashes. A native imported match must then show the custom completed model, damage and persistent selectable ruin; reference validation or an offline preview is insufficient. Do not repeat a blind `options.z` or selector-name patch, and do not replace the final custom art with a stock model.
