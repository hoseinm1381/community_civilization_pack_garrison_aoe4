# Rattan native attachment gate — 0.6.0

**Decision: defer the visual switch.** No isolated research-conditioned
attachment candidate is supported by the pinned native schemas, so no
diagnostic cook or active-source edit was made. The machine-readable receipt is
`output/release_060/rattan-probe/native-gate-v1/qualification.json`.

The six exact Chinese ranged tier attachment records each supply one static
body mesh per variant and no explicit requirement or visibility field. The
source-parity compiled matrix shows each actor's tier list is a complete
`overrideParent=True` replacement with one ordered tier group; neither a
second composing group nor an additive mesh overlay is established. A bounded
decode of three official shield attachment examples showed zero or one static
mesh per variant and no upgrade-conditioned field. The Japanese pavise upgrade
references an unresolved entity action tree; its sampled upgrade and ability
RGDs do not prove how carried equipment is added after research. These records
cannot justify a private fixture that would preserve existing units and
orders, post-research production, tier transitions, weapon actions, and the
actor's stock animation owner.

All six qualified ranged media routes have byte-identical installed-stock
RGO resources, recorded by
`output/release_060/qualification/native-rgo-controls/proof-first49.json`.
That protects the current animation owner but does not provide a conditional
attachment interface. The four editable rattan Blender candidates are retained;
there is no exported modular rattan FBX/LOD overlay to cook. The active
`rattan_armor.scar` and actual `vn_ratten_shield_vit.xml` bytes exactly match
the frozen 0.5.3 sources, so their existing +1 ranged armor path is preserved.

Activation would require a proven native attachment condition/action-tree
schema, an exported compatible overlay, and later native-match checks for old
and new units across research/tier orderings and actions. The 0.6.0 base roster
can proceed with the rattan visual switch deferred; this gate does not claim
import, gameplay, appearance, or multiplayer proof.
