# AoE4 Garrison Blender

Garrison is an AoE4 authoring and packaging extension for Blender. Blender MCP inspects and edits the live Blender file; Garrison owns its game library, project recipes, encoding, cook, and package steps. The AoE4 Content Editor supplies game resource conversion. These are distinct surfaces: an MCP scene edit is not a Garrison build, and a Garrison package is not an in-game result.

## Establish the live context

1. Read the current Blender version, file, dirty state, scene, selection, enabled Garrison extension, its project/library selection, and relevant panel. Preserve unsaved user work. If using Blender MCP, discover and claim the intended instance, start with structured read-only tools, and release the claim before handing control back. Do not save or overwrite a `.blend` unless requested.
2. Open the installed guide from Garrison's book icon or inspect the installed extension under Blender's `extensions` directory. Prefer the live panel and installed guide/source over a remembered operator name or an older screenshot. On 2026-10-11 the installed manifest reported **0.1.4**; all 33 guide pages, four SCAR examples and the mapping preset were reconciled with this skill. That guide reconciliation was documentation-derived; later dated probes have separate evidence. Historical 0.1.0/0.1.3 catalogue and Tuareg evidence retain their dates. Verify again after an update and check the installed client/runtime/audio backend separately; the 0.1.4 release specifies matching components.
   The **2026-10-17 Berber 0.8.1 speech fixture** separately used a normal client identifying as **0.1.6**. Its operator confirmed that the Villager overlap fix worked. This is narrower, newer audio evidence; it does not requalify the whole 0.1.4 authoring guide or imply that every 0.1.6 build implements experimental native-speech APIs.
3. Identify the intended output: a Garrison Mod Project, a separately owned Content Editor project, a Blender Map Creation project, or only scene exploration. A project can start with a blueprint, sound, or map and need no mesh. Confirm project identity before any operation that could overwrite a prior recipe or packaged archive.
4. Treat access tokens and credentials as secrets. Use an already configured connection without printing, copying, saving, or sending its secret. The Garrison extension repository is an extension index, not an MCP endpoint; an inaccessible private index is not a reason to expose a token.

For precise model proportions or contact-critical geometry, use `blender-superskill`. For match-time SCAR and game-mode implementation, use `aoe4-game-mode-skill`; for Attribute Editor XML, use `modify-aoe4-tuning-packs`; for handwritten generated-map terrainlayout Lua, use `create-aoe4-skirmish-map`; for SGA source extraction, use `extract-aoe4-sga-sources`. Garrison's Map Creation workspace is its own generated-map route, separate from handwritten terrainlayout Lua.

For audio-only file/CLI tasks, inspect the installed game/tool versions, project ownership, formats and runtime; no Blender mesh or scene change is needed.

The installed authoring route includes its compiled core/archive tool and prepares model-cook tools from Content Editor. A separate Python/Rust installation or source checkout is not a prerequisite for ordinary panel workflows. Guide contributor commands require their documented source/tool environment. Opening another modder's `.blend` can substitute missing Garrison folder paths with this machine's paths; confirm the current Library/Mod before adding resources.

## Animation evidence status

The inspected public rig guide retains two prototypes and 22 villager/one spearman replacement slots; that panel contract is separate from native engine capability. On **2026-10-24**, a metadata-preserving native RHKA writer and independent predictive encoder produced **new idle and full four-leg walking animations on the unchanged 45-bone cattle skeleton**. Garrison native decoding, public-importer deformation checks, byte-identical owned-runtime rebuilds and strict private-resource packages passed. The user confirmed both buffalo motions worked in-game. Read [Native predictive animation](references/native-predictive-animation.md) for the algorithm, reusable script, native decoder commands, exact artifacts and qualification limits. Do not repeat the historical writer failure as a blanket blocker or bypass panel admission checks.

Earlier Tuareg model/cheer/guard findings retain their scopes; the interruptible private graph/arm-layer route, attack/death replacements, new skeletons and complete motion sets remain unqualified. Read [Animation contracts](references/animations.md) and, for ability motion, [native diagnostics](references/animation-research.md). Keep authoring, encoding, graph integration and gameplay lifecycle separate; `pcall` success is not playback acknowledgement. The buffalo user's brief acceptance does not independently establish every transition, save/load or multiplayer.

## Unit voice routes

For an **import-and-Play Garrison-only release**, read [Scripted unit voices and overlap diagnosis](references/scripted-unit-voices.md) first. The operator-confirmed Berber 0.8.1 route embeds PCM clips, uses `Garrison.audio`, removes the custom units' paired native speech tables, and clears active `attachment_speaker_code` overrides. Villager age/gender attachment lists can explicitly restore original speech even after the main tables are removed. This is a tested scripted replacement layout, not automatic native suppression by `audio.play()` or a universal mute API. Preserve working units and test the changed family in a fresh process.

For native dialogue/efforts, read [Native voice implementation](references/native-voices.md) before choosing the package layout. The qualified Windows route uses a private SPD/WEM companion in the game's existing `audio:` loose folder, both custom EBPS/SBPS speaker bindings, and a compatible Wwise encoder. `data:audio/` does not supply native `audio:`; an Extension `audio` TOC was rejected. Qualify a small audible probe with stock controls before production integration. Voice-only CLI work needs no mesh edit or Blender scene inspection.

The native reference includes coverage/mapping, the bounded Donso profile helper, safe native installation, typed SCAR probe positions, and separate acceptance evidence. The 2026-10-16 two-unit pilot failed; 0.8.1 later resolved the Villager overlap by also clearing its attachment overrides, after a clean-stock-audio test. Keep both findings and their scopes. Do not switch a user who wants Garrison-only voices back to a native companion merely because an older partial attempt failed. Experimental `Garrison.speech` source substitution is a third, separately qualified runtime capability; a `native_speech: no handler` log is not a reason to invent a SCAR mute call. Shared foley/impacts and multiplayer remain separate work.

## Work and verify in stages

- In Blender, inspect source geometry, origin, UVs, materials, texture paths, normals, object names, rig/weights or map markers as applicable. Run Garrison's relevant Check/Validate action and resolve blocking findings before build. Do not assume a Blender viewport preview matches the game.
- For static assets, run Create/Update Asset, Adopt or Bake materials, then Add Asset to Mod. For construction assets use Build Building; for prototype units use Build Unit. Rebuild the affected resource after source edits; Package alone does not export scene changes.
- Cook the mod archive or map and inspect the latest result, named output, logs, and readback where available. An older successful `.sga` can remain after a failed cook.
- Package the successful cooked archive, import the new ZIP into the Garrison client, enable it, and select each required Map, Tuning Pack, and Game Mode in the AoE4 lobby. Enabling does not select it. Ordinary source/model deliveries require Live Reload off and a fresh cook. The qualified direct native-animation route retains verified geometry and writes/readbacks new RHKA plus private bindings; report that route explicitly rather than claiming a fresh model cook or Content Editor burn.
- Report evidence separately: Blender scene/preflight; Garrison export and cook/readback; package/import; lobby selection; native solo-match appearance and behavior. Do not call a source check, cook, or package an in-game pass. The installed guide does not qualify multiplayer generally.
