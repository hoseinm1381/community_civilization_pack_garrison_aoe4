# 0.7.5 candidate rebuild and evidence

This candidate is an explicit art overlay on the frozen 0.7.4 SGA. The active 0.7.4 source identity and delivery are retained. The normal edition is not a build input. Do not run a historical release build to reproduce this candidate: a source-only build would omit required compiled owning-resource overlays.

Run commands from the Garrison root. Native codecs use `E:\Blender5.2\5.2\python\bin\python.exe -B -X utf8`; Blender authoring uses isolated background processes. Never save the unrelated live scene. `workspace.json` and the storage verifier are authoritative for the owned F: targets. Each cook and package attempt requires a fresh label; prior attempts remain evidence.

1. `tools/release_075/verify_preservation.py` checks the immutable baseline, 2,642 historical Garrison files and 298 normal-edition files.
2. Editable revisions live under `art/authoring/release_075`. Their corresponding export directories contain `model.fbx`, `building.json` and four PBR textures. Art receipts identify original hashes, contacts, lifecycle geometry and the exact export hashes. Use the final selection recorded with the delivered candidate, not whichever revision sorts last.
3. `tools/release_075/cook.py FAMILY --revision rN --label NEW_LABEL` creates an isolated Garrison building project, with Live Reload and generated game mode disabled, and performs a fresh native art cook/readback. Citadel and Headquarters have no revision subdirectory, so omit `--revision`. Native builds are serialized through the project lock.
4. `tools/release_075/assemble_media.py FAMILY --label NEW_LABEL` combines fresh geometry and object-PBR materials with the existing private resource keys. It requires exact original selector bytes, markers and every model chunk other than `MSCL`. Existing `.rgo` lifecycle owners are not replaced. Temporary prototype actors are not integrated.
5. `tools/release_075/owner_colour/place.py` derives flag placements from measured support contacts and the actual exported-body/stamp transforms. The final support evidence is frozen in `output/release_075/owner_colour/placements-final-v2.json`. `tools/release_075/cook_flags.py PLACEMENTS_JSON --label NEW_LABEL --reflect-only --stock-deps` compiles native stamp sources using the full Content Editor and reads back their transforms and nonblocking flags. Exact official flag dependencies are staged only for source validation; none are overlaid in the final mod. The official stock flag retains its own shader, mask and lifecycle resources; the custom building bodies retain object-PBR materials. Earlier minimal-editor attempts are retained as diagnostics and must not be selected.
6. `tools/release_075/verify_payloads.py` rechecks available payload receipts. This alone does not select the final seven revisions or prove native behavior.
7. `tools/release_075/select_candidate.py FLAG_RECEIPT PLACEMENTS_JSON NEW_SELECTION_JSON` freezes the explicitly reviewed final source and export revisions. `tools/release_075/package_candidate.py SELECTION_JSON --label NEW_LABEL` consumes exactly seven model payload receipts and one seven-flag receipt. It follows export hashes through the cook input freezes, binds the final placement hash, checks destination identity before assembly and on the final archive, verifies every member hash and original mount, rejects changes outside the explicit visual allowlist, repeats preservation checks, and verifies the ZIP and embedded SGA hash.

The package's `recipe-freeze.json`, `verification.json` and `delivery-proof.json` identify the actual selected inputs and final hashes. The candidate uses strict version `0.7.5`; it does not overwrite the installed mod or the 0.7.4 rollback. No files are deleted by this workflow.

Source-art review, native art cook, native stamp compile, archive/package integrity, and in-game acceptance are separate gates. Read `RELEASE_075_NATIVE_ACCEPTANCE.md` for the final-candidate user test. A successful candidate build does not establish the 9–10 visual target, owner-colour behavior, repair, save/load or multiplayer behavior.
