## Availability and recovery

1. Keep the external drive assigned **F:**. If a link breaks, reconnect it and
   verify the external root and target exist.
2. Run `tools/verify_workspace.py --storage-only`. Guards verify actual junctions
   and their resolved targets; they reject ordinary E: fallback directories.
3. To relocate storage, stop editor/build activity, inventory dependencies, copy
   owned directories and verify every file's SHA-256 before removing an original.
   Update `workspace.json`, this document, and `path-map.json` together, then
   recreate only the verified links.
4. To restore a directory locally, first ensure sufficient E: space. Verify the
   exact junction and external target, remove only the junction without recursing,
   then copy/hash-verify the target into its logical location. Update the guards
   deliberately: current configuration rejects local fallback.

Never rerun external `provenance/initialize_copy.py` against an active destination;
it refuses populated destinations. Use `tools/prepare_garrison.ps1` for repeatable
settings preparation. It does not repair/recreate missing storage links or replace
foreign projects.

Native burners may have path-length limits. Check expanded paths before a future
cook. Use an inventoried task-owned short cook copy within the external staging
root if sufficient, recording configuration/input hashes and verifying readback.
If those paths are still too long, resolve a shorter owned path before cooking;
do not silently create an unowned alias or move the cook onto E:.
